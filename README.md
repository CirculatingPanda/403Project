# Memory Controller Generator v2.1

A high-accuracy SystemVerilog memory controller generator using TAMU AI (Claude Sonnet 4.5).

## Supported Controller Types

| Kind | Complexity | AI Needed? | Expected Accuracy |
|------|------------|------------|-------------------|
| `fifo_controller` | 1/5 | ❌ No | 95%+ |
| `regfile_controller` | 1/5 | ❌ No | 95%+ |
| `rom_controller` | 1/5 | ❌ No | 95%+ |
| `sram_controller` | 1/5 | ❌ No | 90%+ |
| `sdram_controller` | 3/5 | ⚠️ Yes | 60-70% |
| `ddr_controller` | 4/5 | ⚠️ Yes | 40-55% |
| `ddr2_controller` | 5/5 | ⚠️ Yes | 25-45% |

## Quick Start (PowerShell)

```powershell
# 1. Set up environment
Copy-Item .env.template .env
notepad .env  # Add your TAMUS_AI_CHAT_API_KEY

# 2. Install dependencies
pip install python-dotenv requests

# 3. Test with FIFO (no AI needed - fastest test)
python mc_generator_v2.py -s specs/demo_fifo.json -o output_fifo/

# 4. Check output
Get-ChildItem output_fifo/
```

## What Gets Generated Automatically (No AI)

These files are generated by pure Python - no API calls:

- `*_timing_params.svh` - Timing parameters header
- `*.sdc` - Synthesis constraints for Genus/Innovus
- `filelist.f` - Compilation file list

## Testing Strategy

1. **Start with FIFO** - Skeleton is 100% complete, no AI needed
2. **Then SRAM** - Skeleton is 95% complete, minimal AI
3. **Verify synthesis** - Run through Verilator, then Genus
4. **Scale up** - Add SDRAM, DDR skeletons when ready

## Troubleshooting

### "TAMUS_AI_CHAT_API_KEY not set"
- Copy `.env.template` to `.env`
- Add your API key to the `.env` file

### "Skeleton not found"
- Check the `skeletons/<kind>/` directory exists
- Skeleton files must be named `MC_Skeleton_<component>.sv`

### "TODO markers remaining"
- The AI didn't complete all sections
- Try running again (retry logic handles this)
- Or manually complete the remaining TODOs
